Coder v2.38.7 becomes latest stable as v2.39 mainline ships

November 11, 2026 · 2 min read
Julien Antony
Systems tinkerer

Coder moved the 2.38 line to the latest stable release with v2.38.7 on November 10, 2026, carrying a breaking change that validates workspace app URLs on the server. The v2.39 mainline line advanced in the same window: v2.39.0 shipped on November 3 with breaking changes, and v2.39.1 followed on November 10 as a patch release.

Releases​

  • v2.38.7 (Nov 10, 2026): now the latest stable release ("Stable since November 10, 2026"). Breaking change: validate workspace app URLs on the server (#31262). Also fixes: ignore retired OAuth2 scopes such as task:* (#31117) and tighten up database connection errors (#31850). Source: https://github.com/coder/coder/releases/tag/v2.38.7
  • v2.39.0 (Nov 3, 2026): November mainline release. Includes breaking changes, such as the connection log migration that blocks reads and writes during the rewrite of the connection_logs table (#30466). Coder advises enterprise users without a staging environment to stay on the latest stable release while 2.39 is refined. Source: https://github.com/coder/coder/releases/tag/v2.39.0
  • v2.39.1 (Nov 10, 2026): mainline patch release on the 2.39 line, fixing tightened-up database connection errors (#31850) and backporting release calendar and install version documentation refresh for v2.39.0 (#31716). Source: https://github.com/coder/coder/releases/tag/v2.39.1

Fixes and other​

  • Server-side validation of workspace app URLs lands in v2.38.7 as a breaking fix, so misconfigured workspace app URLs are now rejected by the server (https://github.com/coder/coder/releases/tag/v2.38.7).
  • Database connection error handling was tightened on both the 2.38 and 2.39 lines via #31850 (https://github.com/coder/coder/releases/tag/v2.39.1).

Coder 2.39 mainline lands with breaking changes and wide stable backports

November 11, 2026 · 2 min read
Julien Antony
Systems tinkerer

Coder shipped a new mainline v2.39.0 on Nov 3 with breaking changes, followed by v2.39.1 on Nov 10, while the stable lines all moved: v2.38.6 closed security advisory GHSA-cv23-7vc5-jfh7, and v2.38.7 became the new latest stable with a breaking change that validates workspace app URLs on the server. Backport releases v2.37.11 and v2.34.19 followed on Nov 10.

Releases​

  • v2.39.0 (Nov 3) - New mainline release on the 2.39 track. Breaking changes include a connection-log table migration that blocks reads and writes (#30466); Coder advises enterprise users without staging to wait for the latest stable. Source: release page
  • v2.39.1 (Nov 10) - Mainline patch on the 2.39 track that tightens database connection errors (#31850) and backports release calendar and install version documentation refreshes. Source: release page
  • v2.38.6 (Nov 3) - Stable line release marked "Stable (since November 03, 2026)"; bug fixes include bumping gomarkdown/markdown to fix security advisory GHSA-cv23-7vc5-jfh7, plus dependency updates (chi v5.5.0, bundled Terraform 1.17.1). Source: release page
  • v2.38.7 (Nov 10) - Now the latest stable release. Breaking change: workspace app URLs are validated on the server (#31262). Also fixes the server ignoring retired OAuth2 scopes such as task:* (#31117) and tightens database connection errors. Source: release page
  • v2.37.11 (Nov 10) - Backport on the 2.37 line of server-side workspace app URL validation and tightened database connection error handling, plus the session-token restriction to trusted app links in coder open app. Source: release page
  • v2.34.19 (Nov 10) - Backport on the 2.34 line of the same server-side app URL validation and database connection error fixes. Source: release page

LlamaCPP 0.9.0 lands OCP FP8 and a local speech stack

November 11, 2026 · 2 min read
Julien Antony
Systems tinkerer

llama.cpp v0.9.0 shipped on 4 November 2026, adding OCP FP8 E4M3 quantization, a flash_attn_ext_rows op that makes the unified KV cache efficient for multi-sequence inference, and a generic batched tensor copy API. The release expands the audio stack with Chatterbox TTS, Nemotron 3.5 Transcribe and predefined Pocket TTS voices, adds four new architectures (Clover, Limite, Metis-1.6, Mistral Large 4), and bumps ggml to 0.29.0 with early NCCL multi-node tensor parallel. Community coverage on dev.to explored the new local speech stack and its limits on Windows.

Releases​

  • v0.9.0 was released on 2026-11-04 as the latest stable version of llama.cpp. It adds OCP FP8 E4M3 quantization support, the new flash_attn_ext_rows op, a batched tensor copy API, and major prefill optimizations for Gemma 4 E2B/E4B models. (source)
  • v0.9.0 updates ggml to v0.29.0, bringing early NCCL multi-node tensor parallel support. (source)

Features​

  • v0.9.0 adds first-class Chatterbox TTS, Nemotron 3.5 Transcribe and predefined Pocket TTS voices, extending audio generation and transcription in the toolchain. (source)
  • v0.9.0 adds four new model architectures: Clover, Limite, Metis-1.6 and Mistral Large 4. (source)
  • Nightly build b12191 (2026-11-07) introduces a --moe-cache-cpu-share parameter that lets a fraction of Mixture-of-Experts cache misses be computed on the host CPU instead of the primary device, plus a new moe-cache-tune.py script to profile and recommend --moe-cache-mib and CPU share settings. (source)

Community​

  • A dev.to article posted on 2026-11-05 details how v0.9.0's llama-tts tool and multimodal server support make Chatterbox TTS and Nemotron Transcribe usable as a fully local speech stack, and notes that Windows capture-path latency still limits real-time audio. (source)

Features​

  • ninfer-perplexity now accepts rk8v4, rk4v4, rk4v4-e8 and rk2v4-e8 KV dtypes (parser hunk from T-Crypt's PR #16). First used in the 2026-10-24 triage baseline on the v2 artifact: A16 4.363573 vs INT8 4.358936 on the quick corpus. Omarchy 4.5 lands with desktop mode and Apple Silicon support

November 11, 2026 · 2 min read
Julien Antony
Systems tinkerer

Omarchy 4.5 (codenamed Quattro RS) shipped on November 5, 2026 as the project's first big feature release since Quattro, after more than 740 pull requests from 180+ contributors in twelve weeks. The headline changes: a traditional desktop mode alongside the tiling default, native installation on Apple Silicon MacBooks (M1/M2/M3/Neo), and interface support for 50 languages. The project also expanded beyond x86_64 for the first time, with reported support for NVIDIA N1X laptops and DGX Spark, while Snapdragon X laptop support is forthcoming.

Releases​

  • Omarchy v4.5.0 (Quattro RS) was released to GitHub on November 5, 2026: the first major feature release since Quattro, adding a traditional desktop mode next to the tiling default, a native installer for M1/M2/M3/Neo MacBooks, and 50 languages (source).
  • The release was announced on the project's news page on November 4, 2026, with instructions for existing users (Update > Omarchy) and a direct download for new machines (source).

Features​

  • Floating workspaces with a dock: Super + L cycles any workspace between tiling, scrolling, and floating; floating windows get themed titlebars, a dock of pinned and running apps, and Super + M minimizes to the dock (source).
  • Native Apple Silicon support: the Omarchy M team shipped a native Mac installer for M1/M2/M3/Neo MacBooks, building on Asahi Linux work (source).
  • First multi-architecture release: beyond x86_64, Phoronix reports support for Apple Silicon hardware, NVIDIA N1X laptops, and DGX Spark desktops, with Snapdragon X support planned (source).
  • More desktop customizations, including per-monitor workspaces, rebuilt notifications, an Appearance menu, and four new default apps (Hype, Monologue, Signed, Disktree), plus 50 languages (source).

Community​

  • Phoronix covered the release on November 5, 2026, highlighting the distro's expansion beyond x86_64 and its new desktop customization options (source).
