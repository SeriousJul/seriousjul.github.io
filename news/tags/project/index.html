llama.cpp GGUF parser CVEs get third-party review

November 24, 2026 · 2 min read
Julien Antony
Systems tinkerer

Penligent published a review of three llama.cpp GGUF parser vulnerabilities (CVE-2026-126974, CVE-2026-126975, CVE-2026-126976), urging teams to verify which upstream parser fixes their GGUF-loading builds actually contain. In the same window, Microsoft's .NET team published a guide on running local llama.cpp models from .NET apps on Windows via the Llama tray app.

Fixes and other​

  • 2026-11-18: Penligent's Hacking Labs published a security analysis of three llama.cpp GGUF parser CVEs whose Zero Day Initiative advisories (ZDI-26-954, ZDI-26-975, ZDI-26-976) were released Nov 13, 2026. The review covers an integer overflow in GGUF parsing, inadequate length validation before a heap-buffer copy (both linking upstream PR 31336), and an integer overflow when parsing audio multimodal projector GGUF data (a separate commit), and notes the November 18 feed appearance is not a new disclosure date. The practical takeaway: establish which parser fixes, including optional multimodal and control-vector paths, exist in the binary that loads your model files. Source: https://www.penligent.ai/hackinglabs/cve-2026-126974/

Community​

  • Late November 2026 (published 2026-11-23 per the post): Microsoft's .NET team published a guide showing how to run local LLMs in .NET apps on Windows using llama.cpp, built around the Llama on Windows tray app from the Hugging Face and llama.cpp teams, with a sample repo calling a llama.cpp server from a .NET 11 C# file-based app. Source: https://devblogs.microsoft.com/dotnet/local-models-dotnet-llama-windows/

n8n 2.49.0 and 2.50.0 ship, CVE-2026-119408 gets a deep dive

n8n shipped two stable releases this window: 2.49.0 (Nov 17), a broad update centered on AI agents with webhook channels, approval support, agent management, and tool guardrails, and 2.50.0 (Nov 24), which fixed AI Agent chat-memory handling, n8n Assistant behavior, and Public API import/export. Also, TryHackMe detailed CVE-2026-119408, a high-severity code-execution flaw patched in 2.42.6, and Activepieces published a detailed analysis of Nod, n8n's local personal agent.

Releases​

  • 2.49.0 (Nov 17, 2026): broad update focused on AI agents, adding webhook channels, approval support, agent management, skills editing, and tool guardrails; also expands API and OAuth capabilities and fixes numerous reliability, workflow, and editor issues (Releasebot).
  • 2.50.0 (Nov 24, 2026): stable release with bug fixes including AI Agent chat-memory handling (drops turns with empty content), n8n Assistant improvements, Public API behavior for workflow package import/export, and fixes across AWS Bedrock, Baserow, and HTTP Request nodes (n8n CHANGELOG).

Fixes and other​

  • TryHackMe (Nov 23, 2026) detailed CVE-2026-119408 (CVSS 8.7, High): a user with workflow permissions can run JavaScript in the main application process via the deprecated Function, Function Item, and LangChain Code nodes, outside task-runner isolation, which can expose the instance encryption key. The vendor patch shipped in 2.42.6, and the write-up links a hands-on training room (TryHackMe).

Community​

  • Activepieces (Nov 21, 2026) published a detailed analysis of Nod, n8n's local personal agent released as a research preview that can connect to n8n to build, test, and run workflows. As of 2026-11-11, n8n had not published a launch date or source code, and no native third-party integration exists yet (Activepieces).

LlamaCPP v1.0.0: llama.cpp and ggml hit their first stable release

November 20, 2026 · 2 min read
Julien Antony
Systems tinkerer

llama.cpp and ggml have reached their first stable v1.0.0 releases on November 13, 2026, ending roughly three and a half years of sub-1.0 development. The team, which has been developing the project at Hugging Face since February 2026, committed to semantic versioning going forward: major version bumps will only occur for breaking API or ABI changes.

Releases​

  • llama.cpp v1.0.0 and ggml v1.0.0 (November 13, 2026): ggml-org published the first stable 1.0.0 of llama.cpp (libllama) and its underlying ggml library. This marks the first 1.0.0 milestone for the project, which started in March 2023 as an inference engine for Meta's LLaMA model and now supports most open-source LLMs on a wide range of hardware. Future major version updates will be tied to compatibility-breaking API/ABI changes. Source: Hugging Face blog, llama.cpp v1.0.0: A stronger foundation for the local AI ecosystem

Community​

  • Milestone covered by GIGAZINE (November 16, 2026): GIGAZINE reported that llama.cpp and ggml have finally reached version 1.0.0. The article traces the project's history from its March 2023 release by Georgi Gerganov, through its 2026 move to Hugging Face, and notes its role as the underlying engine for popular local AI applications such as LM Studio and Unsloth Desktop. Source: GIGAZINE, 'llama.cpp' has finally reached version 1.0.0
